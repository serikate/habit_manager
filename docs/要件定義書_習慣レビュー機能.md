# 習慣レビュー機能 要件定義書

## 1. 概要

### 1.1 機能の目的
習慣を続けるべきか否かを客観的・主観的な評価に基づいて判断するための機能。
5段階評価のアンケートに回答することで、習慣の継続/調整/中止を数値で判断できる。

### 1.2 背景
- 習慣を漫然と続けることで、本来の目的から外れてしまうことがある
- 短期目標達成に貢献しているかを定期的に振り返る仕組みが必要
- 客観的なデータと主観的な評価を組み合わせて判断したい

---

## 2. 機能要件

### 2.1 アンケート項目

| # | 質問文 | 意図 | 重み |
|---|--------|------|------|
| Q1 | この習慣は短期目標の達成に貢献していますか？ | 目標との紐づき確認 | ×1.5 |
| Q2 | この習慣を目的意識を持って実行できていますか？ | 意識・集中度 | ×1.2 |
| Q3 | この習慣にかけている時間は適切ですか？ | 時間対効果 | ×1.0 |
| Q4 | この習慣は生活リズムに無理なく組み込めていますか？ | 持続可能性 | ×1.0 |
| Q5 | この習慣へのモチベーションは維持できていますか？ | やる気 | ×1.3 |

### 2.2 回答選択肢

| 点数 | 選択肢ラベル |
|------|-------------|
| 5 | 強くそう思う |
| 4 | そう思う |
| 3 | どちらでもない |
| 2 | あまりそう思わない |
| 1 | 全くそう思わない |

### 2.3 スコア計算

```
合計スコア = (Q1×1.5) + (Q2×1.2) + (Q3×1.0) + (Q4×1.0) + (Q5×1.3)
満点 = 5 × (1.5 + 1.2 + 1.0 + 1.0 + 1.3) = 5 × 6.0 = 30点
```

### 2.4 判定基準

| スコア範囲 | 割合 | 判定 | 表示メッセージ |
|-----------|------|------|---------------|
| 24〜30 | 80%以上 | 継続 | この習慣は目標達成に貢献しています |
| 18〜23 | 60%以上 | 調整 | 頻度や方法を見直してみましょう |
| 12〜17 | 40%以上 | 要検討 | 目標との関連を再確認しましょう |
| 0〜11 | 40%未満 | 中止検討 | 別の習慣への切り替えを検討しましょう |

### 2.5 客観データ表示（参考情報）

アンケート回答前に、以下の客観データを表示する：
- 達成率（過去30日）
- 連続記録（現在/最長）
- 継続期間
- 現在のレベル

## 4. データ仕様

### 4.1 レビュー結果の保存

```typescript
interface HabitReview {
  id: string
  habit_id: string
  user_id: string

  // 回答内容
  q1_score: number  // 1-5
  q2_score: number  // 1-5
  q3_score: number  // 1-5
  q4_score: number  // 1-5
  q5_score: number  // 1-5

  // 計算結果
  total_score: number      // 重み付け後の合計
  max_score: number        // 満点（30）
  percentage: number       // パーセンテージ
  judgment: 'continue' | 'adjust' | 'reconsider' | 'stop'

  // メタデータ
  created_at: string

  // レビュー時点の習慣データ（スナップショット）
  snapshot: {
    achievement_rate: number
    streak_current: number
    streak_max: number
    total_days: number
    level: number
  }
}
```

### 4.2 データベーステーブル

```sql
CREATE TABLE habit_reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  habit_id UUID NOT NULL REFERENCES habits(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,

  q1_score INTEGER NOT NULL CHECK (q1_score BETWEEN 1 AND 5),
  q2_score INTEGER NOT NULL CHECK (q2_score BETWEEN 1 AND 5),
  q3_score INTEGER NOT NULL CHECK (q3_score BETWEEN 1 AND 5),
  q4_score INTEGER NOT NULL CHECK (q4_score BETWEEN 1 AND 5),
  q5_score INTEGER NOT NULL CHECK (q5_score BETWEEN 1 AND 5),

  total_score DECIMAL(4,1) NOT NULL,
  percentage DECIMAL(5,2) NOT NULL,
  judgment TEXT NOT NULL CHECK (judgment IN ('continue', 'adjust', 'reconsider', 'stop')),

  snapshot JSONB NOT NULL,

  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- インデックス
CREATE INDEX idx_habit_reviews_habit_id ON habit_reviews(habit_id);
CREATE INDEX idx_habit_reviews_user_id ON habit_reviews(user_id);
CREATE INDEX idx_habit_reviews_created_at ON habit_reviews(created_at DESC);

-- RLS
ALTER TABLE habit_reviews ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own reviews"
  ON habit_reviews FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can create own reviews"
  ON habit_reviews FOR INSERT
  WITH CHECK (auth.uid() = user_id);
```

## 5. 非機能要件

### 5.1 パフォーマンス
- レビュー画面の初期表示: 1秒以内
- スコア計算: クライアントサイドで即時計算

### 5.2 ユーザビリティ
- 全質問が1画面に収まること（スクロール最小限）
- 回答は即時反映（ラジオボタン形式）
- 結果画面は視覚的に分かりやすく表示

### 5.3 データ整合性
- レビュー時点の習慣データをスナップショットとして保存
- 過去のレビュー履歴を参照可能

## 6. 週間レビュー通知機能

### 6.1 基本仕様

| 項目 | 内容 |
|------|------|
| 頻度 | 週1回 |
| デフォルト | 日曜日 18:00 |
| トリガー | 設定時刻以降にアプリを開いたとき |
| スキップ時 | 来週まで非表示 |

### 6.2 通知ポップアップ画面

```
┌─────────────────────────────────────────┐
│  📋 週間レビューの時間です              │
├─────────────────────────────────────────┤
│                                         │
│  習慣の振り返りを行いましょう           │
│                                         │
│  レビューする習慣を選択してください：   │
│                                         │
│  ☑ 早起き習慣        達成率 72%        │
│  ☑ 読書30分          達成率 85%        │
│  ☐ 筋トレ     ⚠️    達成率 45%        │
│  ☑ 瞑想              達成率 60%        │
│                                         │
│  ⚠️ = 達成率50%未満（レビュー推奨）    │
│                                         │
├─────────────────────────────────────────┤
│  [レビューを開始（3件）]                │
│                                         │
│  [スキップ]      [通知設定]             │
└─────────────────────────────────────────┘
```

**動作仕様**:
- 達成率50%未満の習慣に ⚠️ マークを表示
- デフォルトで全習慣にチェックが入っている
- 「レビューを開始」ボタンに選択件数を表示
- スキップ時は来週の設定日時まで非表示

### 6.3 設定画面（設定ページに追加）

```
┌─────────────────────────────────────────┐
│  📋 週間レビュー                        │
├─────────────────────────────────────────┤
│                                         │
│  通知      ────────────○ ON             │
│                                         │
│  曜日      [日曜日 ▼]                   │
│  時間      [18:00 ▼]                    │
│                                         │
│  ※ 指定日時以降にアプリを開くと        │
│    レビュー通知が表示されます           │
└─────────────────────────────────────────┘
```

### 6.4 レビュー設定データ

```typescript
interface ReviewSettings {
  enabled: boolean        // 通知ON/OFF
  dayOfWeek: number       // 0-6 (0=日曜)
  hour: number            // 0-23
  minute: number          // 0-59
  lastSkippedAt: string | null  // スキップした日時
  lastReviewedAt: string | null // 最後にレビューした日時
}
```

### 6.5 表示判定ロジック

```typescript
function shouldShowReviewPopup(settings: ReviewSettings): boolean {
  if (!settings.enabled) return false

  const now = new Date()
  const lastAction = settings.lastReviewedAt || settings.lastSkippedAt

  // 今週の設定日時を計算
  const targetDate = getThisWeekReviewDate(settings)

  // 設定日時を過ぎている AND 今週まだレビュー/スキップしていない
  return now >= targetDate && !isThisWeek(lastAction)
}
```
