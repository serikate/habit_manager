# チュートリアル機能 要件定義書

## 1. 概要

### 1.1 目的
初めてアプリを使用するユーザーが、アプリの趣旨と使い方を理解し、基本的な設定（ビジョン〜習慣の登録）を完了できるようにする。

### 1.2 背景
本アプリは「1年後ビジョン → 長期目標 → 短期目標 → 習慣」という階層構造を持つ。この構造を理解せずに使い始めると、アプリの価値を十分に活用できない可能性がある。

### 1.3 ゴール
- ユーザーがアプリの階層構造を理解する
- 実際にビジョン・長期目標・短期目標・習慣を各1つずつ登録する
- ダッシュボードでの日常的な使い方を理解する

## 2. 機能要件

### 2.1 チュートリアル発動条件

| 条件 | 説明 |
|------|------|
| 初回ログイン | ユーザーが初めてログインした際に自動発動 |
| 手動再実行 | 設定ページの「チュートリアルを再実行」ボタンから発動 |

### 2.2 チュートリアル形式

| 項目 | 仕様 |
|------|------|
| 形式 | ハンズオン形式（実際に作成しないと次に進めない） |
| UI | オーバーレイ + スポットライト方式 |
| ページ遷移 | ボタンをハイライトしてユーザー操作で遷移 |
| スキップ | 各ステップでスキップ可能（全体スキップも可能） |
| 中断再開 | ブラウザを閉じても中断したステップから再開可能 |

### 2.3 チュートリアルフロー

```
【Phase 1: サイドバー説明】場所: ダッシュボード
├─ Step 1: ウェルカムメッセージ（アプリ全体の説明）
├─ Step 2: ダッシュボードの説明
├─ Step 3: 目標管理の説明
├─ Step 4: 習慣管理の説明
├─ Step 5: タスク管理の説明
├─ Step 6: 統計の説明
└─ Step 7: 目標管理ページへの誘導

【Phase 2: 目標管理ページ】場所: /goals
├─ Step 8: ビジョンエリアの説明
├─ Step 9: ビジョン作成ボタンのハイライト → 作成待ち
├─ Step 10: ビジョン作成完了メッセージ
├─ Step 11: 長期目標作成ボタンのハイライト → 作成待ち
├─ Step 12: 長期目標作成完了メッセージ
├─ Step 13: 短期目標作成ボタンのハイライト → 作成待ち
├─ Step 14: 短期目標作成完了メッセージ
└─ Step 15: 習慣管理ページへの誘導

【Phase 3: 習慣管理ページ】場所: /habits
├─ Step 16: 習慣エリアの説明
└─ Step 17: 習慣作成ボタンのハイライト → 作成待ち

【Phase 4: 完了】場所: /habits → /dashboard
└─ Step 18: 完了メッセージ（紙吹雪演出）
```

### 2.4 UI仕様

#### 2.4.1 オーバーレイ
- 画面全体を半透明の黒（rgba(0,0,0,0.7)程度）で覆う
- ハイライト対象の要素のみ切り抜いて表示
- ハイライト部分には光彩エフェクト（box-shadow）を適用

#### 2.4.2 ツールチップ
- ハイライト要素の近くに表示
- 位置は要素の場所に応じて自動調整（上/下/左/右）
- 含まれる要素:
  - タイトル（太字）
  - 説明文
  - 「次へ」または「スキップ」ボタン
  - ステップインジケーター（例: 3/18）

#### 2.4.3 モーダル表示時
- モーダルが開いている間もオーバーレイは継続
- モーダル内の要素をハイライト可能
- モーダル操作は通常通り可能

#### 2.4.4 作成完了時
- 作成成功を検知して自動的に次のステップへ遷移
- 完了メッセージを一時的に表示（2秒程度）

### 2.5 スキップ機能

| スキップ種別 | 動作 |
|-------------|------|
| ステップスキップ | 現在のステップをスキップして次へ進む |
| 全体スキップ | チュートリアル全体を終了する |
| 確認ダイアログ | 全体スキップ時のみ確認ダイアログを表示 |

### 2.6 中断・再開機能

| 項目 | 仕様 |
|------|------|
| 保存タイミング | ステップ遷移ごとに自動保存 |
| 保存先 | Supabase user_settingsテーブル または localStorage |
| 再開条件 | ログイン時に未完了のチュートリアルがあれば自動再開 |
| 再開位置 | 中断したステップの先頭から |

### 2.7 設定ページ連携

設定ページに以下を追加:
- 「チュートリアルを再実行」ボタン
- チュートリアル完了状態の表示（完了済み/未完了）

## 3. 非機能要件

### 3.1 パフォーマンス
- オーバーレイ表示によるレンダリング負荷を最小限に
- スポットライト計算はrequestAnimationFrameで最適化

### 3.2 アクセシビリティ
- キーボード操作対応（Escでスキップ、Enterで次へ）
- スクリーンリーダー対応（aria-label設定）

### 3.3 レスポンシブ対応
- モバイル/タブレット/デスクトップで適切に表示
- ツールチップ位置をビューポートに応じて調整

## 4. データ設計

### 4.1 チュートリアル状態

```typescript
interface TutorialState {
  // チュートリアルがアクティブかどうか
  isActive: boolean

  // 現在のステップID
  currentStepId: string

  // チュートリアル完了済みかどうか
  isCompleted: boolean

  // スキップされたかどうか
  wasSkipped: boolean
}
```

### 4.2 ステップ定義

```typescript
interface TutorialStep {
  // ステップID（一意）
  id: string

  // このステップが表示されるページ
  page: string

  // ハイライト対象のセレクタ（nullの場合は画面中央にメッセージ）
  target: string | null

  // ツールチップのタイトル
  title: string

  // ツールチップの説明文
  content: string

  // ツールチップの位置（auto/top/bottom/left/right/center）
  position: 'auto' | 'top' | 'bottom' | 'left' | 'right' | 'center'

  // ページ遷移を待つ場合のパス
  waitForNavigation?: string

  // アクション完了を待つ場合のアクションID
  waitForAction?: string

  // 完了時に紙吹雪を表示するか
  showConfetti?: boolean
}
```

### 4.3 永続化データ（user_settings）

```sql
-- user_settingsテーブルに追加するカラム
ALTER TABLE user_settings ADD COLUMN IF NOT EXISTS tutorial_completed BOOLEAN DEFAULT FALSE;
ALTER TABLE user_settings ADD COLUMN IF NOT EXISTS tutorial_current_step TEXT DEFAULT NULL;
ALTER TABLE user_settings ADD COLUMN IF NOT EXISTS tutorial_skipped BOOLEAN DEFAULT FALSE;
```

## 6. エラーハンドリング

| ケース | 対応 |
|--------|------|
| ターゲット要素が見つからない | 次のステップへスキップ |
| ページ遷移がタイムアウト | 再試行ボタンを表示 |
| 作成アクションが失敗 | 通常のエラー表示 + チュートリアル継続 |
| ネットワークエラー | 状態をlocalStorageにフォールバック保存 |
