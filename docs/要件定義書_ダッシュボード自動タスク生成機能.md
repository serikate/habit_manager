## 1. 概要

### 1.1 背景
現在、習慣タスクは手動で「今日の習慣タスク生成」ボタンをクリックして生成する必要がある。また、単発タスクと習慣タスクが別々に管理されており、一日の全体像を把握しにくい状況である。

### 1.2 目的
- 日付が変わった際に自動的に習慣タスクを生成し、ユーザーの手間を削減する
- 習慣タスクと単発タスクを統合表示し、一日のスケジュールを一元管理できるようにする
- 今週の予定を可視化し、計画的なタスク管理を支援する

### 1.3 期待効果
- ユーザーの操作負担削減（毎日のボタンクリックが不要）
- タスク管理の見通しが良くなる
- タスクの見落とし防止

## 2. 機能要件

### 2.1 自動タスク生成機能

#### 2.1.1 基本仕様
| 項目 | 仕様 |
|------|------|
| **トリガー** | ダッシュボードページへのアクセス |
| **実行条件** | 最終生成日が今日でない場合 |
| **生成対象** | アクティブな習慣の今日分のタスク |
| **重複防止** | localStorage に最終生成日を保存 |
| **データ保存先** | Supabase `daily_tasks` テーブル |

#### 2.1.2 処理フロー
1. ページロード時に `useDailyTaskAutoGenerator` フックを実行
2. localStorage から `last_task_generation_date` を取得
3. 現在日付と比較
4. 日付が異なる場合:
   - `habitStore.generateHabitTasks('today')` を実行
   - `taskStore.fetchTodayTasks()` でタスクを再取得
   - `taskStore.fetchOneTimeTasks()` で単発タスクを取得
   - localStorage を今日の日付で更新
   - 成功通知を表示
5. エラー発生時:
   - 失敗通知を表示
   - localStorage は更新しない（次回アクセス時に再試行）

#### 2.1.3 通知仕様
| 種類 | メッセージ | 表示時間 | スタイル |
|------|-----------|---------|---------|
| **成功** | `✅ 今日のタスクを{N}件生成しました` | 3秒後に自動で消える | 緑色背景 |
| **失敗** | `❌ タスクの自動生成に失敗しました` | 手動で閉じるまで表示 | 赤色背景 |

---

### 2.2 タスク統合表示機能

#### 2.2.1 エリアA: 今日のタスク

| 項目 | 仕様 |
|------|------|
| **表示対象** | ① 習慣タスク（`daily_tasks`で`is_recurring = true`）<br>② 期限が今日以前の単発タスク（`one_time_tasks`） |
| **フィルタ条件** | 単発タスク: `status != 'completed' AND deadline <= 今日` |
| **ソート順** | `scheduled_time` の昇順（時系列） |
| **期限超過表示** | 赤文字 + ⚠️ アイコン（`deadline < 今日`の場合） |
| **コンポーネント** | `TaskList`（改修版） |

**表示例:**
```
🟢 朝のランニング (習慣) 06:00
🔵 読書 (習慣) 20:00
🔴 プロジェクト資料作成 (単発/今日期限)
⚠️ メール返信 (単発/昨日期限)  ← 赤文字
```

#### 2.2.2 エリアB: 今週の予定

| 項目 | 仕様 |
|------|------|
| **表示対象** | 期限が明日〜設定日数後までの単発タスク |
| **フィルタ条件** | `status != 'completed' AND 今日 < deadline <= 今日+設定日数` |
| **グループ化** | 日付ごとにグループ化 |
| **日付フォーマット** | `📅 MM/DD (曜日)` 例: `📅 10/26 (土)` |
| **折りたたみ** | あり（詳細は後述） |
| **0件時の挙動** | セクションごと非表示 |
| **コンポーネント** | `FutureTasksPanel`（新規作成） |

**表示例:**
```
📅 10/26 (土)
  □ 歯医者の予約
  □ 企画書レビュー

📅 10/27 (日)
  □ チームミーティング資料準備
```

---

### 2.3 折りたたみ機能

| 項目 | 仕様 |
|------|------|
| **対象セクション** | エリアB「今週の予定」 |
| **初期状態** | 閉じている |
| **状態管理** | localStorage に `future_tasks_panel_open` として保存 |
| **開閉操作** | ヘッダー全体をクリック |
| **アイコン** | 開: `▼`、閉: `▶` |
| **タスク数表示** | ヘッダーに件数を表示（例: `4件`） |

---

### 2.4 表示日数設定機能

| 項目 | 仕様 |
|------|------|
| **設定UI** | ダッシュボード内のドロップダウン |
| **配置場所** | 「今週の予定」セクションのヘッダー右側 |
| **選択肢** | 3日後まで / 7日後まで / 14日後まで / 30日後まで |
| **デフォルト値** | 7日後まで |
| **保存先** | localStorage (`future_tasks_days`) |
| **即座反映** | 選択変更時に即座にフィルタリングを再実行 |

**UIイメージ:**
```
▼ 今週の予定 (明日〜7日後) 4件  [7日後まで ▼]
                                    ↑ドロップダウン
```

---

### 2.5 フォールバック機能

| 項目 | 仕様 |
|------|------|
| **目的** | 自動生成失敗時の手動生成手段 |
| **表示条件** | 常に表示 |
| **ボタンラベル** | `今日のタスクを生成` |
| **配置場所** | 「今日のスケジュール」セクションのヘッダー右側 |
| **実行処理** | `generateHabitTasks('today')` を手動実行 |
| **成功時** | タスクリストを再取得して更新 + 成功通知 |
| **失敗時** | 失敗通知を表示 |

## 4. データ仕様

### 4.1 localStorage

| キー名 | 型 | 説明 | デフォルト値 |
|--------|----|----|-------------|
| `last_task_generation_date` | string | 最終タスク生成日（yyyy-MM-dd形式） | null |
| `future_tasks_days` | string | 予定表示日数 | "7" |
| `future_tasks_panel_open` | string | 今週の予定の開閉状態（"true"/"false"） | "false" |

### 4.2 データベーステーブル

#### 使用するテーブル
- **`daily_tasks`**: 習慣タスクの保存先
- **`one_time_tasks`**: 単発タスクの保存先
- **`habits`**: 習慣マスタ
- **`categories`**: カテゴリマスタ

#### データフロー
```
habits (is_active = true)
  ↓ generateHabitTasks()
daily_tasks (新規作成)
  ↓ fetchTodayTasks()
画面表示

one_time_tasks
  ↓ fetchOneTimeTasks()
  ↓ フィルタリング
画面表示
```

## 7. 制約事項・前提条件

### 7.1 制約事項
1. ドラッグ&ドロップ機能は**実装しない**
2. 自動生成はブラウザアクセス時のみ（サーバーサイドの定期実行は行わない）
3. 通知はブラウザの標準通知ではなく、画面内通知バナーを使用
4. TaskListコンポーネントは他ページで使用されていないため、破壊的変更可能

### 7.2 前提条件
1. Supabase接続が正常に動作していること
2. `habits`テーブルに`schedule`フィールドが存在すること
3. `one_time_tasks`テーブルに`deadline`フィールドが存在すること
4. ユーザーが認証済みであること
