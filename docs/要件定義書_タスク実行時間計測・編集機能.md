# 要件定義書：タスク実行時間計測・編集機能

**作成日**: 2025-01-15
**バージョン**: 1.0
**対象機能**: タスクの予定時間表示、実行時間計測、実行時間編集

---

## 1. 概要

### 1.1 目的

ダッシュボードの「今日のタスク」において、以下の機能を実装する：
1. 習慣時間割で設定した予定時間の表示
2. タスク開始〜完了までの実行時間の自動計測
3. 完了後の実行時間の編集機能
4. 編集履歴の記録

これにより、ユーザーは計画と実績を比較し、タスク管理の精度向上と振り返りに活用できる。

### 1.2 適用範囲

- **対象タスク**: 習慣タスク（daily_tasks）
- **対象画面**: ダッシュボード（/dashboard）の「今日のタスク」セクション
- **対象ユーザー**: ログイン済みの全ユーザー

---

## 2. 機能要件

### 2.1 機能1: 予定時間の表示

#### 2.1.1 表示内容

習慣時間割で設定した開始時刻と予想時間から、予定時間帯を表示する。

**表示形式**: `5:30~6:30(60分)`

**構成要素**:
- 開始時刻: `scheduled_time` フィールドの値（例: "05:30"）
- 終了時刻: 開始時刻 + `estimated_duration` 分
- 所要時間: `estimated_duration` の値

#### 2.1.2 表示タイミング

タスクの全ステータスで常に表示する：
- `pending` (未開始)
- `in_progress` (実行中)
- `completed` (完了)

#### 2.1.3 表示位置

TaskList コンポーネント内の各タスクカードにおいて、時計アイコン (Clock) の横に表示する。

#### 2.1.4 scheduled_time 未設定時の動作

習慣時間割で時間を設定していない場合、「時間未設定」と表示する。

---

### 2.2 機能2: 実行時間の自動計測

#### 2.2.1 開始時刻の記録

**トリガー**: ユーザーが「開始」ボタンをクリック

**処理内容**:
1. 現在時刻を取得（ISO 8601形式）
2. `daily_tasks.started_at` に記録
3. `daily_tasks.status` を `'in_progress'` に更新

**データ形式**: `"2025-01-15T05:32:15.123Z"` (ISO 8601, UTC)

#### 2.2.2 完了時刻の記録と計算

**トリガー**: ユーザーが「完了」ボタンをクリック

**処理内容**:
1. 現在時刻を取得（ISO 8601形式）
2. 実際の所要時間を計算: `(完了時刻 - 開始時刻)` を分単位に変換
3. 達成率を計算: `(実際の所要時間 / 予定所要時間) × 100`（上限150%）
4. `task_executions` テーブルに以下を記録:
   - `started_at`: 開始時刻
   - `completed_at`: 完了時刻
   - `actual_duration`: 実際の所要時間（分）
   - `achievement_rate`: 達成率（%）
5. `daily_tasks.status` を `'completed'` に更新

**達成率の計算式**:
```javascript
achievement_rate = Math.min((actual_duration / estimated_duration) * 100, 150)
```

#### 2.2.3 実行中の表示

タスクが `in_progress` 状態の間は、実績時間を表示しない。予定時間のみ表示する。

#### 2.2.4 完了後の表示

**表示形式**: `5:32~6:42(70分)`

**追加表示**: 達成率 `達成率116%`

**色分け**:
- 100%以内: 緑色 (`text-green-600`) ✅
- 101%〜120%: 黄色 (`text-yellow-600`) ⚠️
- 121%以上: 赤色 (`text-red-600`) ❌

---

### 2.3 機能3: 実行時間の編集

#### 2.3.1 編集可能条件

- タスクのステータスが `'completed'` であること
- task_executions レコードが存在すること

#### 2.3.2 編集UI

**UI形式**: モーダルダイアログ

**表示トリガー**: 完了済みタスクの「✏️編集」ボタンをクリック

**編集項目**:
1. 開始時刻（time input）
2. 終了時刻（time input）
3. 編集理由（textarea、任意）

**自動計算項目**:
- 所要時間: `(終了時刻 - 開始時刻)` を分単位で表示
- 達成率: `(所要時間 / 予定所要時間) × 100`

#### 2.3.3 バリデーションルール

編集時に以下をチェックする：

| 項目 | ルール | エラーメッセージ |
|------|--------|------------------|
| 時刻の順序 | 開始時刻 < 終了時刻 | 「終了時刻は開始時刻より後である必要があります」 |
| 所要時間の上限 | 所要時間 ≤ 1440分（24時間） | 「所要時間は24時間以内である必要があります」 |
| 未来時刻の禁止 | 終了時刻 ≤ 現在時刻 | 「未来の時刻は入力できません」 |
| 負の値の禁止 | 所要時間 ≥ 0 | 「所要時間が負の値になっています」 |

#### 2.3.4 データ更新対象

**更新対象**: `task_executions` テーブルのみ

**更新しないデータ**: `daily_tasks.started_at` は変更しない
- 理由: 実際にボタンを押した時刻として保持

**更新内容**:
```sql
UPDATE task_executions
SET
  started_at = [編集後の開始時刻],
  completed_at = [編集後の終了時刻],
  actual_duration = [再計算された所要時間],
  achievement_rate = [再計算された達成率]
WHERE id = [execution_id]
```

---

### 2.4 機能4: 編集履歴の記録

#### 2.4.1 履歴記録のタイミング

実行時間の編集を保存する際、編集前後の値を `task_execution_edits` テーブルに記録する。

#### 2.4.2 記録内容

| フィールド | 内容 |
|-----------|------|
| execution_id | 編集対象の task_executions.id |
| old_started_at | 編集前の開始時刻 |
| old_completed_at | 編集前の完了時刻 |
| old_actual_duration | 編集前の所要時間 |
| old_achievement_rate | 編集前の達成率 |
| new_started_at | 編集後の開始時刻 |
| new_completed_at | 編集後の完了時刻 |
| new_actual_duration | 編集後の所要時間 |
| new_achievement_rate | 編集後の達成率 |
| edited_by | 編集したユーザーのID |
| edited_at | 編集日時 |
| edit_reason | 編集理由（任意） |

#### 2.4.3 履歴の表示

**Phase 1では実装しない**（将来の拡張として検討）

将来的には以下の場所で履歴を確認できるようにする：
- タスク詳細画面
- 統計・振り返り画面

## 4. データベース設計

### 4.1 テーブル変更

#### 4.1.1 daily_tasks テーブル

**追加カラム**:

| カラム名 | データ型 | NULL許可 | 説明 |
|---------|----------|---------|------|
| started_at | TIMESTAMPTZ | YES | 実際の開始日時 |

**制約**:
- なし（NULL許可）

#### 4.1.2 task_executions テーブル

**追加カラム**:

| カラム名 | データ型 | NULL許可 | 説明 |
|---------|----------|---------|------|
| started_at | TIMESTAMPTZ | YES | 開始日時（編集可能） |

**既存カラムの利用**:
- `completed_at`: 完了日時（編集可能）
- `actual_duration`: 所要時間（編集後再計算）
- `achievement_rate`: 達成率（編集後再計算）

### 4.2 新規テーブル

#### 4.2.1 task_execution_edits（編集履歴）

| カラム名 | データ型 | NULL許可 | 制約 | 説明 |
|---------|----------|---------|------|------|
| id | UUID | NO | PRIMARY KEY | 履歴ID |
| execution_id | UUID | NO | FOREIGN KEY | 編集対象のexecution ID |
| old_started_at | TIMESTAMPTZ | NO | - | 編集前の開始時刻 |
| old_completed_at | TIMESTAMPTZ | NO | - | 編集前の完了時刻 |
| old_actual_duration | INTEGER | NO | - | 編集前の所要時間（分） |
| old_achievement_rate | DECIMAL(5,2) | NO | - | 編集前の達成率 |
| new_started_at | TIMESTAMPTZ | NO | - | 編集後の開始時刻 |
| new_completed_at | TIMESTAMPTZ | NO | - | 編集後の完了時刻 |
| new_actual_duration | INTEGER | NO | - | 編集後の所要時間（分） |
| new_achievement_rate | DECIMAL(5,2) | NO | - | 編集後の達成率 |
| edited_by | UUID | NO | FOREIGN KEY | 編集ユーザーID |
| edited_at | TIMESTAMPTZ | NO | DEFAULT NOW() | 編集日時 |
| edit_reason | TEXT | YES | - | 編集理由 |
| created_at | TIMESTAMPTZ | NO | DEFAULT NOW() | レコード作成日時 |

**インデックス**:
- `idx_task_execution_edits_execution_id` ON `execution_id`
- `idx_task_execution_edits_edited_at` ON `edited_at DESC`

**外部キー制約**:
- `execution_id` → `task_executions(id)` ON DELETE CASCADE
- `edited_by` → `auth.users(id)`

## 5. 非機能要件

### 5.1 パフォーマンス

- 時間計算処理は1秒以内に完了すること
- モーダルの表示は0.3秒以内に完了すること
- データベース更新は2秒以内に完了すること

### 5.2 ユーザビリティ

- time input は HH:MM 形式で直感的に入力可能
- バリデーションエラーは明確なメッセージで表示
- 編集モーダルは ESC キーで閉じられる
- 所要時間と達成率はリアルタイムで再計算される

### 5.3 セキュリティ

- 編集操作は認証済みユーザーのみ実行可能
- 他ユーザーのタスクは編集不可（RLSで制御）
- 編集履歴には編集者のuser_idを記録

### 5.4 保守性

- 時間計算ロジックはユーティリティ関数として分離
- バリデーションロジックは再利用可能な形で実装
- 型定義は types/index.ts に集約

## 6. 制約事項

### 6.1 Phase 1 の制約

以下の機能は Phase 1 では実装しない：

1. 編集履歴の表示UI
2. 一時停止・再開機能
3. リアルタイムでの経過時間表示（実行中）
4. 単発タスク（one_time_tasks）への対応

### 6.2 技術的制約

- ブラウザのタイムゾーンに依存するため、ユーザーのローカル時刻で表示
- タイムゾーン変更時の挙動は考慮しない
- オフライン時の操作は未対応

## 7. 受け入れ基準

### 7.1 機能テスト

| テストケース | 期待結果 |
|------------|---------|
| scheduled_time設定済みタスクの表示 | 「5:30~6:30(60分)」形式で予定時間が表示される |
| scheduled_time未設定タスクの表示 | 「時間未設定」と表示される |
| 開始ボタンクリック | started_at が記録され、ステータスが in_progress になる |
| 完了ボタンクリック | 実績時間が正確に計算され、task_executions に記録される |
| 達成率の計算 | 予定60分、実績70分の場合、116%と表示される |
| 達成率の色分け | 100%以下は緑、120%以下は黄、121%以上は赤 |
| 編集ボタンの表示 | 完了済みタスクのみ編集ボタンが表示される |
| 編集モーダルの表示 | 既存の開始・終了時刻が入力欄に反映される |
| 時刻編集時の自動計算 | 時刻変更時に所要時間と達成率が即座に更新される |
| バリデーション | 開始時刻 ≥ 終了時刻の場合、エラーメッセージが表示される |
| 編集の保存 | 編集内容が task_executions に反映される |
| 編集履歴の記録 | task_execution_edits に編集前後の値が記録される |

### 7.2 データ整合性テスト

| テストケース | 期待結果 |
|------------|---------|
| 完了前にリロード | started_at が保持されている |
| 完了処理の失敗 | daily_tasks の started_at は残り、再試行可能 |
| 編集の取り消し | 元のデータが保持される |
| 複数回編集 | 編集履歴が全て記録される |
